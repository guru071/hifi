# HIFI Security Posture

## 1. Authentication
HIFI uses **Firebase/Supabase Authentication** exclusively. Session tokens are generated by the auth provider and decoded on the backend for verification. No independent password hashing logic exists in the codebase.

## 2. Admin Authorization (Rule 20)
Admin configuration routes like `PUT /api/products/[id]` and `POST /api/settings` do not rely on frontend UI obfuscation. They employ hard server-side gates:
- The `Authorization` Bearer token is parsed.
- `supabase.auth.getUser(token)` validates identity.
- The user's role is checked against the database (`role === 'admin'`).

## 3. Data Integrity & Trust (Rule 18)
The backend **never trusts** the frontend for:
- Prices (Server recalculates cart totals dynamically against `base_price`).
- Inventory (Server-side Stored Procedure atomically decrements stock via `FOR UPDATE` locking).
- Payment Status (Server requires a verifiable cryptographic Razorpay webhook/callback).
- Reviews (Server requires a verified purchase matching `order_items`).

## 4. Environment Variables
No secrets are committed to the repository. Variables like `RAZORPAY_KEY_SECRET` are strictly kept server-side.
